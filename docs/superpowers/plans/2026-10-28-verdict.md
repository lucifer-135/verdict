# Verdict Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Verdict, a mobile-first web app that tells a user whether a skincare product is working, using repeated YouCam Skin Analysis scans, a noise-aware verdict engine and a Skin Simulation goal preview.

**Architecture:** Next.js 15 App Router app on Vercel. Route handlers are a thin proxy to YouCam (key stays server-side). All user data (scans, trials, photos, masks) lives in IndexedDB on the device. The verdict engine is a pure TypeScript module.

**Tech Stack:** Next.js 15, TypeScript (strict), Tailwind CSS, Recharts, `exifr`, `idb`, `date-fns`, Vitest + Testing Library + `fake-indexeddb`, `tsx` for scripts. Node 24 (local).

**Spec:** `docs/superpowers/specs/2026-10-28-verdict-design.md`

## Global Constraints

- YouCam API key lives only in server env `YOUCAM_API_KEY`. Never use a `NEXT_PUBLIC_` variable for it.
- Env vars: `YOUCAM_API_KEY`, `YOUCAM_BASE_URL` (default `https://yce-api-01.makeupar.com`), `YOUCAM_MOCK` (`1` = fixtures, no units).
- Every check-in scan is SD with all 16 concerns: `wrinkle`, `droopy_upper_eyelid`, `droopy_lower_eyelid`, `firmness`, `acne`, `moisture`, `eye_bag`, `dark_circle_v2`, `age_spot`, `radiance`, `redness`, `oiliness`, `pore`, `texture`, `tear_trough`, `skin_type`. No HD.
- Verdict logic uses `raw_score` only. `ui_score` appears only in the scan report.
- Polling: every 2 s, timeout 90 s. A timeout retries polling the same task, never creates a new task.
- Image prep: short side ≥ 480 px, long side ≤ 2560 px, JPEG quality 0.9, final size ≤ 4 MB.
- Goal simulation intensity: 0.4 for every simulable target concern.
- Default noise band: 3 raw points.
- Tests never call the real YouCam API. They use mocked `fetch` or fixtures.
- No face photos committed to git except the consented sample set in `public/sample/`. Spike and sample source photos go in `.local/` (gitignored).
- Exact copy: disclaimer "Cosmetic insight, not medical advice."; sample badge "Sample".
- Mobile-first: layout designed at 375 px width, single column, max width 480 px centered. Must work in iOS Safari and Android Chrome.
- Verdict chip labels and colors: `too_early` "Too early" (slate-400), `working` "Working" (emerald-600), `give_it_time` "Give it time" (amber-500), `not_moving` "Not moving" (zinc-500), `pause` "Pause" (rose-600).
- Dates: trial `startDate` is `YYYY-MM-DD` local; scan `takenAt` is ISO 8601. Day math uses `date-fns` `differenceInCalendarDays` in local time. Display format `MMM d` (e.g. "Sep 15").
- **Plan decision (spec gap):** next check-in date = last scan date + 7 days; shown as "Today" when on or past due.

## Review Focus

1. **Sample scans leaking into real trials, or real scans into the sample trial.** Expected: a real trial only sees `camera`/`import` scans; the sample trial only sees `sample` scans. Test: Task 7 `scansForTrial` tests.
2. **Trial with no scans, or a start date in the future.** Expected: verdict `too_early` with a sensible message, no crash or NaN. Test: Task 2 engine tests "no scans" and "future start date".
3. **`/api/asset` used as an open proxy (SSRF).** Expected: only `https` URLs on allowlisted YouCam result hosts are fetched; anything else returns 400. Test: Task 4 asset route tests.
4. **Camera unavailable** (plain-http LAN address, permission denied, desktop with no camera). Expected: the scan screen falls back to a file picker with `capture="user"`. Test: Task 8 `CameraCapture` fallback test.
5. **Importing the same photo twice.** Expected: the duplicate is skipped before any API call, so no units are spent and no scan is double-counted. Test: Task 10 dedupe test.

  ```ts
  type ScanSource = 'camera' | 'import' | 'sample';
  interface ConcernScore { raw: number; ui: number }
  interface Scan {
    id: string; takenAt: string; source: ScanSource; sourceHash: string | null;
    photoBlobId: string; overall: number | null; skinAge: number | null;
    scores: Partial<Record<ConcernId, ConcernScore>>;
    maskBlobIds: Partial<Record<ConcernId, string>>; skinType: string | null;

  interface Trial {

    goal: TrialGoal | null; createdAt: string; isSample: boolean; archived: boolean;
  }
  type VerdictKind = 'too_early' | 'working' | 'give_it_time' | 'not_moving' | 'pause';
  interface ConcernVerdict {
    concern: ConcernId; kind: VerdictKind; baseline: number | null; delta: number | null;
    slope: number | null; noise: number; goal: number | null; goalProgress: number | null;
  }
  interface SideEffect { concern: ConcernId; delta: number; noise: number }
  interface VerdictResult {
    kind: VerdictKind; reason: string; confidence: 'low' | 'medium' | 'high';
    perConcern: ConcernVerdict[]; sideEffects: SideEffect[]; goalProgress: number | null;
    overlapWarning: string | null; lateBaseline: boolean; daysIn: number;
  }
  ```
- Produces (`lib/verdict/engine.ts`): `computeVerdict(trial: Trial, scans: Scan[], otherTrials: Trial[], today: Date): VerdictResult`, `NOISE_DEFAULT = 3`.
  The caller passes only the scans that belong to this trial (Task 7 `scansForTrial`).

**Algorithm (implement exactly; spec §4):**
- `day(scan)` = `differenceInCalendarDays(new Date(scan.takenAt), parseISO(trial.startDate))`. `daysIn` = same for `today`.
- Per concern, use only scans that have `scores[concern]`, sorted by `takenAt`.
- Baseline scans: `day ≤ 3`. If none, baseline = first scan, `lateBaseline = true`, and post-baseline = scans after it.
- `baseline` = mean raw of baseline scans. `noise` = `max(3, max − min)` of baseline raws when ≥ 2 baseline scans, else 3.
- `delta` = mean raw of the last 2 post-baseline scans (or the only one) − baseline. `null` if none.
- `slope` = least-squares slope of raw vs `day` over baseline + post-baseline scans; `null` if < 2 distinct days.
- Side effects: every targetable non-target concern with `delta ≤ −noise` goes in `sideEffects`.
- Trial verdict, first match wins:
  1. `pause`: post-baseline count ≥ 1 and (any target `delta ≤ −noise`, or non-target `redness`/`acne` `delta ≤ −2 × noise`).
  2. `too_early`: no scans; or post-baseline count < 2; or `daysIn < 14`.
  3. Per target: `working` if `delta ≥ noise && slope > 0`; else `give_it_time` if `daysIn < windowDays`; else `give_it_time` if `delta ≥ noise` (trending down); else `not_moving`. Trial: `working` if any target is working, else `give_it_time` if any, else `not_moving`.
- Confidence: post-baseline count 2 → low, 3–4 → medium, ≥ 5 → high; forced low when `lateBaseline`.
- Goal progress per concern: `clamp(delta / (goal − baseline), 0, 1)` when goal and delta exist and `goal − baseline > noise`, else `null`. Trial `goalProgress` = mean of non-null values, else `null`.
- Overlap: first other trial with `!archived && !isSample && id !== trial.id` sharing a target concern `c` where `|differenceInCalendarDays(other.start, trial.start)| < windowDays(c)`.
- Points shown = `Math.round(Math.abs(delta))`; weeks = `Math.floor(daysIn / 7)`.

**Reason copy (exact; `{label}` from catalog, `{label_lc}` lowercased):**
- no scans: `Take a baseline scan to start.`
- pause (target): `{label} got worse by {pts} pts since baseline. Possible irritation. Consider pausing; see a dermatologist if it persists.`
- pause (side effect): `{label} got worse by {pts} pts since you started. Possible irritation. Consider pausing; see a dermatologist if it persists.`
- too_early, `daysIn < 14`: `Too early to judge. First fair read on {start + 14 days}.`
- too_early, too few scans: `Too early to judge. Your first fair read comes after your next check-in.`
- working: `{label} improved {pts} pts in {weeks} weeks, above normal scan noise (±{noise}). Keep going.`
- give_it_time (in window): `No clear change yet. Most products need about {window/7} weeks for {label_lc} — keep going until {start + window}.`
- give_it_time (trending down): `{label} improved, but it's trending down lately. Check again in a week.`
- not_moving: `No measurable change after {weeks} weeks. Consider stopping — save your money.`
- `too_early` copy precedence: no scans for any target → "Take a baseline…"; else `daysIn < 14` → date copy; else → next-check-in copy.
- Late baseline: append ` Late baseline (day {N}); earlier changes not counted.`
- Multi-target: the reason uses the first target (in `trial.concerns` order) whose kind equals the trial kind.

- Dev cache: active only when `NODE_ENV === 'development'`. It keys on SHA-256 of bytes + endpoint + actions, stores the final success result in `.cache/youcam/<key>.json`, and returns task id `cached:<key>`.
